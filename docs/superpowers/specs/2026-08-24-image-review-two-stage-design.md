# 图审核两段式重构设计

> 日期：2026-08-24  
> 状态：待用户确认 spec  
> 相关任务：706 / 707（同图同规则、视觉判定不一致）

## 背景与问题

当前图审核由视觉模型**同时**完成「识图 + 判定」：

- 提示词较长，且含通用判定原则，易对简短配置（如「路线图」）自行加严（正式施工图、医院图标等）。
- 通过列表只展示 `passed=true` 的 `image_items`，「识别出的图内容」在不通过时看不到。
- 完整提示词依赖全局「记录每步拼接提示词」；未开调试或命中缓存时，展开常采不到。
- 多图为「逐图视觉判定 + any-pass」，描述分散，不易对照节点级短要求。

## 目标

1. **展示完整**：不论通过与否，「识别出的图内容」列有值；左侧 `+` 可展开完整图审核提示词。
2. **提示词精简精确**：模板仅三类简单配置（存在性 / 图种 / 内容要素）；系统提示词短、不堆加戏标准。
3. **职责分离**：视觉模型只识别图内容；真正审核用与方案内容审核同款的**文本大模型**。
4. **多图合并审核**：同一节点多张图的描述放在一起，由文本 LLM 一次判定。
5. **通过语义**：至少一张图满足已启用要求 → 节点通过（保持现有 any-pass）。
6. **图审核提示词始终落盘**：不依赖全局调试开关。

非目标：改模板三类勾选的产品结构；改工作流步骤顺序；用视觉模型继续做通过/不通过判定。

## 已确认决策

| 项 | 选择 |
|----|------|
| 多图通过规则 | A：至少一张满足 → 节点通过 |
| 提示词落盘 | A：图审核始终落盘识图描述 + 审核提示词 |
| 架构 | 两段式：视觉描述 → 文本 LLM 节点级一次判定 |

## 架构

```text
节点启用图审核
    │
    ├─ 收集 [附图]
    ├─ 存在性（确定性代码，不调模型）
    │     勾选且 0 张 → 不通过，结束本节点视觉/审核
    │
    └─ 需要图种/内容要素
          ├─ 逐图：视觉 → { kind, description }   （可缓存）
          ├─ 一次：文本 LLM ← 精简要求 + 全部图描述
          │         → passed, summary, issues, matched_image_indexes
          └─ 落盘：每图描述、节点审核提示词、image_items、issues
```

文本审核模型：复用内容审核默认文本 LLM（当前如 DeepSeek），不新增独立「图审核文本模型」配置（除非后续有独立诉求）。视觉模型配置保持现有「图审核（视觉模型）」设置。

## 提示词设计

### 视觉识图（每图，极短）

```text
用一两段中文描述这张图实际看到的内容。
必须包含：
1) 图种（如：路线图/平面布置图/照片/表格截图/其他）
2) 图上可见的关键文字、标注、符号、路径或对象
不要判断是否合格，不要引用章节要求。
```

结构化输出：`{ "kind": string, "description": string }`。  
前端「识别出的图内容」：`kind` + `description` 拼接展示。

### 文本 LLM 审核（每节点一次）

```text
根据【审核要求】与下列【附图识别结果】判定本章节附图是否通过。
规则：至少一张图满足全部已启用的要求 → 通过；否则不通过。
只依据识别结果中的可见内容，不要臆造图上没有的信息。
图说明仅供参考，不作为通过条件。
图种匹配时语义同类即可（如「路线图」含导航/路径规划截图），不要额外提高标准。

【审核要求】
- 图种：{kind_note}        （未启用则省略）
- 内容要素：{content_note} （未启用则省略）
【全局规则】…               （模板有配置才附）

【附图识别结果】
图1：图种=…；描述=…
图2：…

输出 JSON：passed, summary, issues[], matched_image_indexes[]
```

存在性不进入该 prompt（代码已处理）。

### 模板 note 约定

| 类别 | 示例 note | 含义 |
|------|-----------|------|
| 是否有图 | 施工总平面布置图 | 仅缺图报错文案 |
| 图种识别 | 路线图 | 识别图种属该类即可 |
| 内容要素 | 集合点、疏散方向 | 描述中须出现这些要素 |

## 数据形态

### `image_items[]`（每张参与展示的图一行，含不通过）

| 字段 | 说明 |
|------|------|
| `template_node_id`, `title_path`, `review_category` | 同现有 |
| `image_object_key`, `image_caption` | 同现有 |
| `kind`, `description` | 视觉识别结果；`summary` 兼容旧字段 = `「{kind}。{description}」` 拼接 |
| `passed` | 该图是否落入文本 LLM 的 `matched_image_indexes` |
| `issues` | 可选，该图相关问题摘要 |
| `review_prompt_text` | **始终写入**：本节点发给文本 LLM 的完整审核提示词（同节点多图各行内容相同，便于行展开） |
| `describe_prompt_text` | **始终写入**：该图识图短 prompt（可选展示） |

### 提示词落盘规则

- 图审核**不**再依赖 `prompt_debug_enabled`；上述字段写入 `image_items` / 报告 JSON。
- `debug_prompts` 可继续附带图审核条目以兼容旧调试 UI；人工审核页图审核展开**只读** `image_items[].review_prompt_text`。

### 步骤 `issues`

- 存在性失败、缺图 info、溢出、视觉/文本调用失败等，同现有语义。
- 文本 LLM 判定不通过时的问题列表；带图时 `related` 含 `image_object_key`，并可关联对应 `description`。

### 缓存

拆两段指纹（版本号 bump，如 `img-3`）：

1. **识图缓存**：图内容 SHA256 + 视觉模型 + `max_side` + 识图 prompt 版本。  
2. **审核缓存**：图描述集合 + kind/content notes + 全局规则 + 文本模型 + 模板 `updated_at` + 审核 prompt 版本。

改审核文案可不重跑视觉；改图或视觉模型才重跑识图。  
调试开关**不再**跳过图审核落盘；若保留「强制重跑」，应做成显式「跳过缓存重审」，与「是否记录提示词」解耦。

## 前端（人工审核页）

### 附图明细表（替换仅展示通过项的「通过列表」）

列：结果（通过/不通过）| 审图类别 | 审核图 | 章节位置 | 识别出的图内容  

- `dataSource = step.image_items`（全部）。  
- 行展开：展示本节点 `review_prompt_text`（无则提示旧任务无落盘数据）。  
- 可选第二块：识图 prompt。

### 问题列表

保留；对有图 issue 展示缩略图，并尽量展示对应「识别出的图内容」。

### 与全局调试开关

| | 图审核 | 其他步骤 |
|--|--------|----------|
| 提示词落盘 | 始终 | 仍跟 `prompt_debug_enabled` |
| 查看入口 | 附图表 `+` | 原调试 Collapse |

## 错误与边界

| 情况 | 行为 |
|------|------|
| 仅存在性、有图 | 不调视觉/文本；可写存在性通过的 image_item 或仅 summary |
| 勾选图种/要素但无图 | 现有缺图文案（`image_review_missing_text`） |
| 视觉单图失败 | 该图无描述；其余图仍可审；全失败则 info，不缓存失败态 |
| 文本 LLM 失败 | 步骤记错误/info；不把不确定结果当通过 |
| 超 `max_per_node` | 同现有：只审前 N 张 + info |
| 旧任务结果 | 无新字段时列显示 `-` / 展开提示旧版 |

## 兼容性

- 模板 `image_review` JSON 结构不变。  
- 报告 `version` / 缓存 `IMAGE_REVIEW_VERSION` 递增，避免旧缓存污染。  
- API 对 `image_items` 增字段向后兼容；旧前端忽略新字段仍可跑。

## 测试要点

1. 单图 + 图种「路线图」+ 导航截图 → 描述含路线图类 → 文本判定通过。  
2. 同图两次任务（非强制重跑）→ 识图/审核缓存命中时结论稳定。  
3. 多图：一张路线图 + 一张无关照片 → 节点通过；`matched` 指向路线图。  
4. 全部不满足 → 节点不通过；明细表仍显示每图识别内容；`+` 有审核提示词。  
5. 关闭全局调试开关仍能展开图审核提示词。  
6. 存在性缺图 → 不调视觉；问题列表有缺图文案。
