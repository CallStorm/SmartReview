# 方案审核列表精简（管理员列过多）

日期：2026-08-28  
范围：`frontend` 方案审核任务列表 UI  
状态：已评审（对话确认方案 A）

## 问题

管理员在「方案审核」列表中同时看到 ID、用户名、方案类型、文件、状态、创建时间、审核耗时、消耗词元（输入/输出两行）以及最多 7 个操作链接，横向拥挤、文件名被截断、视觉噪音大。

## 目标

在不减少管理员能力的前提下，主表更清爽：常用信息一眼可见，次要指标与低频操作二次点击可达。

## 非目标

- 不改后端 API、权限模型、导出/删除/AI 测评业务逻辑
- 不做用户可配置「列设置」
- 不改数据看板或其它页面的表格

## 方案概要（方案 A）

精简主表列 + 操作「主操作 + 更多」+ 行展开承载次要指标。

### 主表列

| 列 | 管理员 | 普通用户 | 说明 |
|---|---|---|---|
| 用户名 | ✓ | — | 现有逻辑 |
| 文件 | ✓ | ✓ | 主行：文件名（ellipsis + Tooltip）；副行小字：`方案类型`（`分类 / 名称`）；Tooltip 可附 `#任务ID` |
| 状态 | ✓ | ✓ | 不变 |
| 创建时间 | ✓ | ✓ | 短格式 `MM-DD HH:mm`，Tooltip 显示完整 `created_at` |
| 操作 | ✓ | ✓ | 见下节 |

主表**不再单独成列**：ID、方案类型、审核耗时、消耗词元。

### 行展开（expandable）

展开后展示只读明细：

- 管理员：任务 ID、完整方案类型、审核耗时（分钟）、输入词元、输出词元
- 普通用户：审核耗时（分钟）、总词元（与现主表非管理员展示一致）

### 操作列

**外露：**

1. 人工审阅（任务未结束时禁用 + Tooltip，逻辑不变）
2. 导出方案（同上）

**「更多」Dropdown（`MoreOutlined`）：**

| 菜单项 | 管理员 | 普通用户 | 备注 |
|---|---|---|---|
| 审核报告 | ✓ | ✓ | 未结束禁用 |
| 审核日志 | ✓ | — | |
| AI测评 | ✓ | — | 仅 succeeded 可点 |
| Word 报告 | ✓ | — | 未结束禁用 |
| 删除 | ✓ | — | 危险样式；仍用 Popconfirm |

操作列目标宽度：管理员约 200px，普通用户约 160px。

## 实现落点

- `frontend/src/pages/ReviewPage.tsx`：列定义、时间格式化、文件+方案类型合并单元格、`expandable`、操作区 Dropdown
- `frontend/src/pages/ReviewPage.css`：文件副行、展开明细、操作列间距
- `frontend/src/config/adminManualContent.ts`：管理员手册「方案审核」描述与新交互对齐（一句更新即可）

## 验收标准

1. 管理员主表无独立 ID / 方案类型 / 耗时 / 词元列；展开可见上述信息。
2. 操作列仅「人工审阅」「导出方案」「更多」；菜单内功能与现网一致（禁用条件、Popconfirm、导航与导出回调不变）。
3. 普通用户无「用户名」列，无管理员专属菜单项。
4. 默认分页下列表示意更宽敞，文件名截断明显减轻。

## 风险与注意

- Dropdown 内「删除」需保持 Popconfirm，避免误删。
- 展开行与 `Table` 现有 `size="middle"`、分页配置兼容；勿引入横向滚动依赖。
- 手册截图可后续再换；本次至少更新文案，避免仍写「主表展开 Token」而实际已迁到行展开。
